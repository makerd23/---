# Bejeweled Blitz 自動遊玩

適用於 Windows 上用 Chrome 開啟的 Facebook 版。程式會開啟遊戲頁面、辨識開始按鈕、交換寶石，並在結算後接著玩下一局。使用 Python 標準函式庫與 Windows 內建的 GDI/GDI+，不需 pip 安裝套件。

1. 雙擊 `start.cmd`。程式會切到現有的 Chrome 遊戲視窗，或開啟 Facebook 遊戲頁面。若需要 Facebook 登入，請完成登入。
2. 程式會辨識 **NO THANKS**、**PLAY AGAIN**、**PLAY**，依畫面自動點擊。棋盤出現後會自動定位，等倒數結束才交換。每局結束後會接著開下一局。
3. 保持棋盤與按鈕完整可見，遊玩中維持視窗大小、網頁縮放和捲動位置。按 **F8** 可停止。

帶到老師電腦時，複製整個 Bejeweled Blitz 資料夾，需有 Windows、Python 3 和 Chrome。四個 .py 檔與 `menu_buttons.json` 請放在一起。啟動器使用 `-S`，可在不載入已安裝套件的狀態下執行。

也可以使用 [寶石方塊自動遊玩.ipynb](寶石方塊自動遊玩.ipynb)。這份筆記本已內嵌程式與按鈕資料，可單獨下載。在 VS Code 選擇可用的 Python 核心後按「全部執行」，按 F8 或中斷核心即可停止。筆記本需要 Jupyter／ipykernel 執行環境。

其他執行方式：

- `.\start.cmd --once`：自動開局，玩一局後停止。
- `.\start.cmd --wait-key`：切到遊戲分頁，按 F2 待命，再用滑鼠開局，玩一局後停止。
- `.\start.cmd --dry-run`：按 F2 待命並手動開局，只印出棋盤與建議走法。

按鈕辨識依據提供的四張英文遊戲畫面。遇到其他彈窗、版面改變或按鈕被裁切時，程式會等待，超過三分鐘會顯示錯誤原因。加時和稀有寶石提示會選擇 NO THANKS。

棋盤編號為紅 1、橘 2、黃 3、綠 4、藍 5、紫 6、白 7，0 表示辨識不明。火焰以 F 註記，例如 3F 是黃色火焰寶石。程式保留寶石顏色，優先選擇能消除已辨識火焰寶石的合法交換。

若自動定位失敗，可執行 `.\start.cmd --manual`。先用一局顯示棋盤，游標指向棋盤左上、右下角各按一次 **F2**。只框 8×8 格，時間條和外框留在外面。下一局開局前再按 **F2** 待命。

若程式提早停止，同資料夾的 `blitz-last-run.log` 會記錄最近一次的定位進度和錯誤原因。

版本 `2026-11-10-recovery`：原本取色不明時，會再取寶石中央的顏色確認。至少辨識到 48 格時，可在已確認且連續兩幀穩定的局部區域交換，不會因其他地方有 8 格無法辨識就封鎖全部走法。六秒無法交換時會持續重新擷取，直到找到走法、遊戲時間結束或按 F8，並每六秒顯示狀態。

每局第一次持續卡住時，會自動保存當下的 `board.png`（棋盤）、`capture.png`（包含時間條）與 `details.json`（格子位置、編號和擷取範圍）。檔案放在 `blitz-diagnostics` 的時間戳記資料夾，完整路徑與無法辨識的位置會顯示在 ipynb 的執行格下方。筆記本以目前工作目錄存檔。更新後請重新開啟筆記本、重新啟動核心，再按「全部執行」，確認輸出顯示版本 `2026-11-10-recovery`。

切到其他分頁或視窗時，程式會暫停操作。切回原本的遊戲分頁後會繼續偵測。遊戲自己的倒數可能仍在進行。

程式等倒數文字消失，確認準備交換、消除的位置及相鄰格連續兩幀一致，再嘗試交換。未知格不會被當作任意顏色，也不會沿用上一幀猜測未知格。火焰也需連續兩幀辨識到才會優先處理，其餘走法依照四連、五連、交叉消除及可從目前棋盤預估的連鎖排序。權重是估計，實際分數需從遊戲結算驗證。火焰辨識依據寶石上緣額外的黃色光芒，動畫和裁切位置可能影響判斷，仍需實際對局驗證。爆炸範圍、其他種類的特殊寶石與新落下的寶石尚未納入預估。
